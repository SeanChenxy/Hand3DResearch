# ForeHOI: Feed-forward 3D Object Reconstruction from Daily Hand-Object Interaction Videos

**Authors:** Yuantao Chen, Jiahao Chang, Chongjie Ye, Chaoran Zhang, Zhaojie Fang, Chenghong Li, Xiaoguang Han  
**Date:** 2026-06-20  
**Identifier:** [arXiv:2602.06226](https://arxiv.org/abs/2602.06226)

## Summary

ForeHOI is a feed-forward model that directly reconstructs complete 3D object geometry from monocular hand-object interaction videos in about one minute of inference, with no pre-processing such as structure from motion, separate inpainting models, or radiance-field optimization. Its central idea is to jointly denoise 2D object mask inpainting and 3D shape completion in a dual-branch diffusion transformer connected by bidirectional cross-attention, so that the two tasks mutually guide each other under severe hand-induced occlusion. Trained exclusively on a newly released synthetic dataset of more than 400K multi-view hand-object interaction video clips built from GraspXL grasp synthesis over Objaverse objects, it achieves state-of-the-art reconstruction on HO3D (0.79 cm Chamfer distance, 93.72 percent F-score at 10 mm, versus 0.86 cm and 91.87 percent for MagicHOI) and HOT3D (89.1 percent F@10 versus 34.25 percent for EasyHOI), with an average inference time of 1.1 minutes against 58 to 330 minutes for optimization-based baselines, roughly a 100x speedup.

## Background and Problem

Daily monocular videos of hand-object interactions are an abundant resource for embodied intelligence, and 3D hand reconstruction from such videos is mature, but reconstructing the involved objects has lagged for two reasons: hands and object self-occlusion leave large parts of the object unobserved, and the camera, hands, and object are all dynamic, making relative camera-object motion estimation difficult. The task the paper defines is complete object geometry recovery from daily hand-object interaction videos, which necessarily requires strong object priors. Existing prior-driven pipelines are problematic: EasyHOI reduces the problem to a single image using pretrained 2D inpainting plus 3D generation, discarding temporal and multi-view information; MagicHOI integrates a novel-view synthesis model into radiance-field optimization but its staged pipeline accumulates view-inconsistent errors and takes hours; a VGGT-plus-completion route fails when structure from motion produces poor initials under severe occlusion, which is common in daily scenes. More generalizable feed-forward object methods impose constraints (depth input, known object pose, rigid interactions, multi-view observation, category-level optimization) that daily hand-object videos violate.

## Method

The framework builds on the TRELLIS and ReconViaGen generation stack. For conditioning, each frame is encoded with DINOv2, and hand features are extracted from the ViT backbone of a state-of-the-art hand pose estimation model (of the WiLoR family); hand patch features are aggregated with DINOv2 patch features patch-to-patch into a 2048-dimensional fused feature that a two-layer MLP projects back to 1024 dimensions. Because features are pixel-aligned they carry local camera-space information, avoiding multi-frame scale inconsistency, and no separate hand or object masks are needed at inference. The core is a dual-branch diffusion transformer: a geometry branch denoises a 64x64x64 latent into coarse object structure conditioned on multi-view aggregated features through weighted cross-attention fusion, while a mask branch predicts per-frame complete object masks. Bidirectional cross-attention couples the branches: mask-branch features replace the geometry branch's input features layer by layer from shallow to deep, and 3D features are fed back into the mask branch as contextual signals, in the spirit of ViLBERT. Because multi-view features are fused through weighted cross-attention rather than concatenation, the model accommodates relatively long input sequences with modest memory growth. Training minimizes a conditional flow matching objective on both the 2D mask and the 3D latent with a shared random timestep, combining the two losses with a balancing weight; a masked multi-view structured-latent (SLat) flow, following TRELLIS but taking occluded object images and DINOv2 features instead of VGGT features (unreliable under heavy occlusion), refines the voxel latent into a mesh. Object pose is estimated afterward by render-and-compare: 30 reference images rendered from viewpoints on a sphere are concatenated with the input frames and passed through VGGT for coarse poses, and Mast3R correspondences with a PnP solver and RANSAC iteratively refine them, with textures produced by a texture stage trained on the new dataset.

## Contributions

The paper claims three contributions. First, ForeHOI is the first feed-forward method to predict object geometry from daily monocular hand-object interaction videos within one minute, eliminating cumbersome pre-processing. Second, it shows that jointly generating 2D object mask inpainting and 3D object completion inside one framework addresses severe hand-object occlusion, with information exchange between the branches boosting overall reconstruction quality. Third, it contributes the first large-scale synthetic hand-object interaction dataset, more than 400K video clips rendered with high-fidelity images and comprehensive annotations (hand masks, object masks, hand poses, object poses, and depth maps), created by adding parametric hand textures with randomized skin tone to MANO hands, selecting quality-filtered GraspXL grasping sequences on Objaverse objects, and rendering multi-view videos in Blender with automatic camera trajectories and randomized lighting. The dataset ablation is itself an argument for the contribution: a ReconViaGen backbone trained on generic object data with random masking reaches only 25.54 percent F@5 on HO3D, because 3D generative models rely on object-centric orientation priors and random occlusions carry no interaction semantics, whereas the same backbone trained on the new data reaches 53.64 percent.

## Experimental Setup

The model adopts the TRELLIS architecture and fine-tunes its diffusion transformers in both stages with LoRA (rank 64, alpha 128, zero dropout, inserted into qkv and output projections). During training, 2 to 6 input views are drawn per sample, images are resized to 518 by 518 (37 by 37 patches) while the hand extractor takes 224 by 224 inputs, and multi-view images from different timestamps are randomly mixed as augmentation. Training uses Adam at learning rate 5e-4 with total batch size 32 and takes 4 days on eight NVIDIA L20 40G GPUs; the model is trained only on the synthetic dataset, with no fine-tuning on real data. Evaluation covers HO3D-v3, using the 14 sequences of the HOLD protocol divided into 30-frame clips, and the egocentric VR-captured HOT3D, preprocessed into 6 short clips of 5 to 15 frames, with single-view baselines averaged per view. Metrics are Chamfer distance in centimeters, F-score at 5 mm and 10 mm, and visual-odometry pose metrics (absolute trajectory error and relative pose error). Baselines are HOLD, EasyHOI, MagicHOI, and HORT (the latter only on HOT3D since it was trained on HO3D), with Dynhor and HOLD for pose comparison.

## Results

On HO3D, ForeHOI obtains 0.79 cm Chamfer distance, 68.95 percent F@5, and 93.72 percent F@10, beating MagicHOI (0.86, 64.53, 91.87), HOLD (1.36, 66.42, 82.43), and EasyHOI (1.83, 46.35, 69.24). On HOT3D the gap widens to 1.03 cm, 60.5 percent F@5, and 89.1 percent F@10 against EasyHOI (1.21, 18.46, 34.25) and HORT (2.32, 16.52, 20.43), the latter failing to generalize to unseen objects and unusual viewpoints. Average inference time is 1.1 minutes for ForeHOI versus 58 minutes for MagicHOI, 175 minutes for EasyHOI, and 330 minutes for HOLD, while the per-image HORT is faster at 0.8 minutes on its setting but fails to transfer. For object pose on HO3D, the render-and-compare scheme reaches 1.42 cm relative pose error, 2.64 degrees relative rotation error, and 0.13 m absolute trajectory error, versus 4.25, 5.25, and 0.24 for Dynhor and 5.87, 6.24, and 0.27 for HOLD, whose structure-from-motion initialization is unreliable under sparse viewpoints. The ablation on HO3D isolates each design: moving from generic multi-view training data with random masking (1.23 cm, 25.54, 68.54) to the hand-object interaction data gives 0.91, 53.64, 80.63; adding hand features yields 0.88, 54.53, 85.43, completing object geometry under contact areas; adding the 2D mask completion branch brings the final 0.79, 68.95, 93.72.

## Limitations

The paper does not include a dedicated limitations section, so the following constraints are read from the reported evidence rather than an explicit discussion. Evaluation is limited in scale, using 14 HO3D sequences and 6 preprocessed HOT3D clips. Pose estimation depends on generated object textures, which the paper itself describes as not perfect, and on a render-and-compare loop built from VGGT, Mast3R, and PnP refinement; the Dynhor pose comparison additionally uses only that method's first-step pose because its refinement stage is not open-sourced. Training data are constrained to GraspXL grasps on quality-filtered Objaverse objects with plausible texture and movement, so dataset coverage bounds the object distribution, and the motivation for the synthetic data rests on the observed failure of object-centric pretraining under hand occlusion. HORT, by contrast, is faster per image at 0.8 minutes on its setting, though it fails to generalize to unseen HOT3D objects.
