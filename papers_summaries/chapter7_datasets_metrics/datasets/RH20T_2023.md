# RH20T (2024)

> Hao-Shu Fang, Hongjie Fang, Zhenyu Tang, Jirong Liu, Chenxi Wang, Junbo Wang, Haoyi Zhu, Cewu Lu (Shanghai Jiao Tong University). *RH20T: A Comprehensive Robotic Dataset for Learning Diverse Skills in One-Shot.* arXiv (preprint, 2024). Zotero Key: `T9AFT6JV` (Note: the PDF attachment of this Zotero entry is actually the GraspXL paper, which does not match RH20T; this summary is based on the RH20T project page and official information). Project: https://rh20t.github.io/.

## Summary
RH20T is a large-scale, real-world, multi-modal, human-robot paired demonstration robotic manipulation dataset: 110,000+ contact-rich manipulation sequences, 147 tasks (48 RLBench + 29 MetaWorld + 70 self-proposed), 7 robot embodiments, 5+ synchronized data streams (RGB, Depth, IR, Force/Torque, Audio, Joint, Tactile). It is the flagship dataset for one-shot imitation learning on complex contact tasks.

## 1. Dataset Purpose
- Solves the fundamental problem of "small scale, single embodiment, single modality, vision-only" of existing robotic datasets. RH20T directly targets the ultimate goal of one-shot imitation learning: "an agent generalizing to hundreds of real skills with multi-modal perception".
- Tasks: (1) one-shot imitation learning (transferring trained policies to new tasks based on demonstrations); (2) multimodal policy learning; (3) contact-rich manipulation; (4) cross-embodiment transfer; (5) vision-tactile-audio multi-modal fusion.
- Strictly speaking, RH20T is a robot-object interaction rather than hand-object, but each sequence provides a human demonstration video, making it simultaneously a data source for hand-object research.
- Anchors "contact-rich + multi-modal + multi-embodiment + human-robot paired" as the evaluation standard.

## 2. Data Composition
- Source: real robot teleoperation (haptic device + pedal for intuitive remote control), covering multiple labs and multiple operators.
- Viewpoint: 8–10 global RGBD cameras per platform + 1–2 in-hand cameras + robot body sensors + 2 microphones; multi-platform shared calibration.
- Scale: 110,000+ contact-rich robot manipulation sequences; about 5 TB (RGB) / 10 TB (RGBD); the original 40 TB.
- Tasks: 147 categories — 48 RLBench + 29 MetaWorld + 70 self-proposed daily tasks (pick, place, push, insert, articulated, etc.).
- Objects: covering daily household and industrial tools (specific numbers to be confirmed in the paper).
- 7 robot configurations (cfg1–cfg7) covering Franka Panda, xArm, and other embodiments.

## 3. Annotation and Supervision
- Robot: joint angle (10 Hz), joint torque (10 Hz), gripper Cartesian pose (100 Hz), gripper width (10 Hz), 6/7-DoF depending on the robot.
- Force / touch: 6-DoF Force / Torque (100 Hz), fingertip tactile (only cfg7, 200 Hz, 2×16×3 sensors).
- Vision: 1280×720 RGB (10 Hz), depth at the same resolution (10 Hz), binocular IR (10 Hz); 4K industrial RGBD (partial).
- Audio: 30 Hz.
- Human-hand demonstration: each robot sequence is paired with a human demonstration video (the key basis of one-shot imitation learning).
- Metadata: camera calibration (all cameras calibrated to the robot base frame), temporal synchronization.
- No language instruction (some task descriptions are mentioned in the paper).

## 4. Supported Evaluation
- Benchmark tasks: (1) one-shot imitation learning (task success rate given 1 human demo); (2) multimodal policy learning; (3) cross-embodiment transfer; (4) contact-rich manipulation.
- Key metrics: task success rate, trajectory error, cross-embodiment transfer rate, force / torque prediction error.
- Mainly used as a pretraining corpus; held-out tasks for evaluation.
- Cross-embodiment split (cfg1–cfg7) for evaluation.
- Cross-task split for evaluating generalization to a held-out subset of the 147 tasks.

## 5. Why It Matters
- One of the few real robotic datasets at the time (2024) that simultaneously has large scale + multi-modal + multi-embodiment + human-robot paired + real environments.
- The combination of 110K+ sequences + 147 tasks + 7 embodiments is unrivaled in the "one-shot imitation learning" direction.
- Multi-modal sensing (force / tactile / audio) makes it unique in contact-rich manipulation.
- Bridges the HOI community and the robot learning community: human demonstration is the source of hand-object models, and robot data is the deployment target of policies.
- Promotes "real-world contact-rich 1-shot" as a new baseline for robot learning.
- The core citation in the "embodied learning data sources" section of Ch6, connecting the method evaluation of Ch2–Ch5 to downstream robotic deployment.

## 6. Limitations and Biases
- Teleoperation demonstration has an embodiment gap: human hand dexterity far exceeds the robot gripper.
- Mainly tabletop / kitchen / industrial desktop operations, with no mobile manipulation, whole-body, or dynamic tasks.
- Although there are 147 tasks, the demonstrations per task are still limited (the specific number per task needs to be checked in the paper).
- Demonstration quality varies with operator skill.
- Part of the data needs to be downloaded via Rclone from Google Drive / Baidu Cloud, which is convenient for domestic access but slightly slower for international access.
- The PDF attachment of this Zotero entry is suspected to be the GraspXL paper (not the original RH20T), and the metadata may not correspond exactly; it needs to be verified.
- Among the 7 robot embodiments, fingertip tactile is only provided by cfg7.

## 7. Takeaway
RH20T is best for demonstrating the capability of "large-scale multi-embodiment real robot data + cross-task one-shot skill learning + multi-modal fusion". **Not suitable** for evaluating dexterous hand-level reconstruction, articulated HOI 4D mesh reconstruction, in-the-wild egocentric HOI tasks, or language-conditioned VLA (only basic task descriptions). In this survey, RH20T plays the role of "robot-side HOI large-scale benchmark + cross-embodiment + multi-modal source", serving as the core anchor of the "embodied learning" section in Ch6, connecting the method evaluation of Ch2–Ch5 to downstream robotic deployment. **The entry content may need to be updated after the Zotero metadata is verified.**
